# Q.E.D. Lite Conventions for Aider
# Drop as .aider.conventions.md or .aider.conventions.lite.md in repo root

## Cognitive Priming & "QED" Trigger
- **Ambient Memory**: Permanently bound by Q.E.D. runtime. All invariants active on every turn regardless of casual prompting.
- **On Mention of "QED"**: Instant Mode A lock (cancel shortcuts), mandatory Pre-Flight check (Grep existing, Blast radius, Red test), and mandatory terminal verification (`qed check` / test suite) with real output.

Directives:
- Prime Directive: Evidence Before Assertions. Never state code works without executing terminal tests.
- Mode A (Default: Quality > Speed): TDD, Blast Radius, 4 States, Verification Gate. Mode B (Speed Mode): Only on explicit request ("quick", "draft", "prototype", "быстро"). Disclose technical debt.
- Root Cause Only: Ban on empty catch blocks, fake timeouts, and loose `any` casts.
- Pristine Root: Zero scratch files or temporary dumps in root.
- Anti-Duplication: Search repo before introducing any new function, hook, or type. Always reuse existing code.
- Blast Radius: Map direct callers and transitive API/DB/cache impact before modifying shared code.
- Security & Hygiene: Never commit secrets; update `.env.example`; bounded LRU caches (`maxSize` + `ttlMs`); cleanup temp files in `try...finally`.
- 4 Mandatory States: Implement Empty (0 items + CTA), Loading (no CLS), Error (actionable + retry), Degraded/Offline (timeout fallback).
- Ironclad TDD: Reproduction test first for bugs (Red -> Green -> Refactor). Zero placebo mocks; zero flaky `sleep()`; cover boundary matrix (0, 1, N, Max, null, hostile Unicode `👨‍👩‍👧‍👦`, double-clicks in 50ms).
- The 3 AM Test: Early returns, flat guard clauses, descriptive variables, positive predicates (`isActive`), units in numbers (`timeoutMs`), contract verbs (`get`, `create`). Comment WHY, not WHAT. Actionable `TODO(#issueId)`.
- Commits: Use Conventional Commits (`feat:`, `fix:`, `test:`, `refactor:`, `docs:`, `chore:`). Keep commits atomic.
- Verification Gate: Purge debug prints and scratch files; run typecheck, linter, and full test suite before completion.
