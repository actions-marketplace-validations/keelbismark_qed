# Руководство по началу работы с Q.E.D. (Quick Start Guide)
> Quod Erat Demonstrandum: Доказательства важнее утверждений.

Это практическое пошаговое руководство для инженера: как установить Q.E.D., авторизовать проект и работать в паре с ИИ-агентами по канонам высокой инженерной строгости (High-Assurance Runtime).

---

## 1. Что такое Q.E.D. простыми словами

Q.E.D. — это не просто markdown-промпт, а **инженерный рантайм и механический гейткипер** для разработки с искусственным интеллектом (Google Antigravity, Cursor, Claude Code, Windsurf, Copilot, Codex и др.).

Он решает три главные проблемы генеративного кода:
1. **Галлюцинации и догадки (Zero Speculation)**: агент обязан опираться на физические факты рантайма, а не угадывать форму контрактов.
2. **Велосипедостроение (Anti-Duplication)**: агент обязан переиспользовать существующие утилиты и хелперы, а не плодить дубликаты.
3. **«Всё работает, мамой клянусь» (Verification Gate)**: любые заявления агента о готовности ничтожны без реального вывода тестов и линтера в терминале.

## 2. Шаг 1: Глобальная установка (Один раз на машину)

Чтобы CLI `qed` был доступен в терминале, а плагин и скиллы подключились к твоим IDE и агентам:

### Вариант A: Через npm
```bash
npm install -g qed-standard
```

### Вариант B: Через скрипт установки из репозитория
```powershell
# Windows PowerShell
.\install.ps1 -Target global
```
```bash
# Linux / macOS / Git Bash
./install.sh --target global
```

**Что происходит при глобальной установке:**
- В твоём профиле регистрируются конституции агентов (`~/.gemini/GEMINI.md`, `~/.cursorrules`, `~/.claude/CLAUDE.md`).
- В `~/.gemini/config/plugins/qed` разворачивается нативный плагин со стартовым хуком (`SessionStart`) и скиллами (`using-qed`, `systematic-debugging`, `qed-reconnaissance` и др.).
- Утилита `qed` становится доступна в терминале как глобальная команда.

## 3. Шаг 2: Инициализация в проекте (`qed init`)

В корне любого репозитория (нового или существующего) выполни:

```bash
qed init
```
*(Или без глобальной установки: `npx qed-standard init`)*

Команда отрабатывает за **~15-30 миллисекунд** и выполняет 6 обязательных шагов:

1. **Stack Telemetry**: определяет языки (TypeScript, Go, Rust, Python и др.), пакетные менеджеры, фреймворки и тестовые раннеры.
2. **Earned Complexity Profile**: считает объём строк (SLOC), плотность кода и присваивает ранг заработанной сложности:
   - `Tier 1 (Utility / CLI)`: до 1,500 строк кода (плоская структура, без абстракций).
   - `Tier 2 (Service / Application)`: 1,500 – 20,000 строк (модули, ограниченные LRU-кеши).
   - `Tier 3 (Platform / Multi-tenant)`: от 20,000 строк (суверенные домены).
3. **Детектор «насрано» (Architectural Findings)**: механически находит архитектурный долг:
   - Год-файлы (> 600–1000 строк или > 35% всей кодовой базы).
   - Преждевременные корпоративные слои (`domain/`, `repositories/` в микро-скриптах).
   - Дыры в тестах (0 тестов на проект > 300 строк).
4. **Anti-Duplication Atlas**: сканирует каталоги `utils/`, `helpers/`, `lib/` и извлекает список существующих функций, чтобы агент не писал велосипеды.
5. **Создание паспорта кодовой базы**:
   - Генерирует `.qed/BRIEF.md` — документ для мгновенной ориентации агента на Turn 0.
   - Создаёт `.qedrc.json` с правилами под твой стек и ранг сложности.
   - Устанавливает адаптеры под используемые IDE (Cursor, Claude, Antigravity).
   - Добавляет официальный щит Q.E.D. в `README.md`.
6. **Git Verification Gate**: устанавливает хуки `.git/hooks/pre-commit` (`qed check`) и `.git/hooks/pre-push` (`qed test`).

> **Совет:** Чтобы сразу увидеть паспорт кодовой базы в терминале, запусти:
> ```bash
> qed init --explore
> ```

## 4. Шаг 3: Как работать с агентом в повседневной разработке

Благодаря хуку `SessionStart` и Turn-0 Priming тебе **больше не нужно писать длинные промпты с правилами**.

### Триггер Q.E.D.
Если нужно гарантировать максимальную строгость, просто упомяни **«qed»** или **«по qed»** в запросе:
> *«Добавь эндпоинт списания с кошелька по qed»*  
> *«Найди причину бага в авторизации по qed»*

Агент немедленно блокирует режим прототипа и переходит в **Mode A (Quality > Speed)**:
1. Открывает `.qed/BRIEF.md` и проверяет существующие хелперы.
2. Рассчитывает радиус поражения (Blast Radius).
3. Пишет падающий тест воспроизведения (Red).
4. Исправляет первопричину (Green).
5. Проводит Mutation Check.
6. Запускает `qed check` в терминале и даёт реальный вывод как доказательство.

### Сценарий 1: Расследование бага или сбоя
Ты пишешь:
> *«При клике на оплату вылетает 500 ошибка»* или *«Почему сервис перезагрузился?»*

**Что делает агент под Q.E.D.:**
- Активирует скилл `systematic-debugging`.
- Снимает физическую телеметрию (дампы, логи системы, коды событий, стек-трейс).
- Трассирует поток данных назад к источнику сбоя.
- Создаёт воспроизводящий тест.
- Устраняет причину, а не затыкает симптом.

### Сценарий 2: Разработка новой фичи
Ты пишешь:
> *«Сделай фильтрацию каталога по диапазону дат»*

**Что делает агент под Q.E.D.:**
- Проверяет Атлас анти-дублирования: находит существующие утилиты работы со временем.
- Проверяет 4 обязательных состояния: пустой список, загрузка со скелетоном, ошибка с кнопкой «Повторить», деградация при таймауте.
- Пишет код по «Тесту 3 часов ночи»: ранние возвраты, плоские условия, понятные имена.

## 5. Шаг 4: Команды CLI для инженера

Все команды выполняются быстро (большинство за 5–15 мс) без внешних зависимостей:

| Команда | Зачем нужна |
| :--- | :--- |
| `qed init [path]` | Полная авторизация и разведка проекта, генерация `.qed/BRIEF.md` и хуков |
| `qed init --explore` | Вывод полного паспорта кодовой базы и атласа хелперов в терминал |
| `qed check [path]` | Проверка репозитория на 16 механических инвариантов Q.E.D. |
| `qed check --strict` | Строгий режим (предупреждения считаются ошибками) |
| `qed check --compact` | Сверхкомпактный однострочный вывод (для AI-агентов) |
| `qed doctor` | Аудит здоровья репозитория: Git, хуки, дрифт адаптеров, REA, CUA, CI |
| `qed hook` | Переустановка Git-хуков `pre-commit` и `pre-push` |
| `qed update` | Синхронизация установленных в проекте адаптеров со свежей версией стандарта |
| `qed update --global` | Синхронизация глобальных конфигураций пользователя |
| `qed test` | Запуск полного кроссплатформенного тестового набора стандартов |

---

## 6. Чеклист готовности проекта к сдаче (Verification Gate)

Перед тем как принять работу у агента или сделать коммит в основную ветку, убедись:

- [ ] В терминале выполнен `qed check` $\rightarrow$ статус **100% CLEAN (0 violations)**.
- [ ] Запущен проектный тестовый набор (`npm test`, `pytest`, `go test ./...`) $\rightarrow$ все тесты зеленые.
- [ ] `git diff` проверен: нет забытых `console.log`, пустых `catch`, `as any` и временных файлов.
- [ ] Хук `pre-commit` отработал без предупреждений.
